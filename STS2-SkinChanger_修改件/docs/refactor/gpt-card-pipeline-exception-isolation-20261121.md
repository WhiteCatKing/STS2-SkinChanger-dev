# #280 / #281 卡牌显示管线异常隔离

## 接入点

卡牌模块为 `NCard._EnterTree`、`_Ready`、`UpdateVisuals(PileType, CardPreviewMode)` 和 `Reload()` 安装同一个 Harmony finalizer。正式版 v0.111.1 和测试版 v0.113.1 的程序集都包含这四个入口。两端 IL 都显示模型、可见性设置器和 `_Ready` 会直接调用 `Reload()`，它可以在 `UpdateVisuals` 之前进入。处理限于卡牌节点显示入口。抽牌、出牌队列、牌库和网络消息处理沿用原代码。

## 异常归因

- 从最内层异常栈开始，跳过 Godot、Harmony 与 BCL 帧，用第一条能判定归属的非框架帧识别抛出方。反射包装的内层只剩框架帧时，才检查外层栈。游戏及切换器自身的异常原对象返回给 Harmony。无栈、来源不明的动态帧或多个独立原因也照常传播。
- 确认是第三方时，finalizer 让调用方继续。按实际程序集与被补丁目标方法在进程内去重，警告一条 `[卡牌管线] 已隔离第三方异常: <Mod 名或程序集名> <方法> <类型>`。优先取已加载 Mod 清单上的名字。
- 本边界不重跑已经中断的函数，异常之后本次未执行的步骤仍未执行。#278 的卡图生命周期和 AI_silent 托管时的专用拦截沿用原实现。

## 测试入口

`--test-card-pipeline-exception`，并入完整无参 RuntimeTests。离线用真实 `NCard` 方法和 Harmony，替换引擎相关方法体以验证控制流。专项覆盖两种第三方后置的 `ObjectDisposedException`、按两目标各记一次、Godot/BCL 反射包装归因、卡牌原方法抛出的同一异常对象、第三方调用栈上的切换器自身异常，以及无归属和多原因异常继续传播。

## 验证结果

正式版 v0.111.1（Release）和测试版 v0.113.1（ReleaseBeta）均 0 警告、0 错误。两端新增专项、LogicTests、完整无参 RuntimeTests 和 `check-protected-characters.ps1` 全部通过，测试版额外的天音／贞德实包测试也通过。日志位于 `%TEMP%/sts2-gpt-280/official-281.log` 和 `beta-281.log`。未提交、未部署。

## 实机复测

1. 用测试版和报告的 Mod 组合，先保留原生先加载的第三方卡图包以覆盖 #278 专用拦截之外的路径。进局抽牌、打开牌库、退主菜单后继续同一局，再抽牌、打开牌库、打出卡牌。
2. 条件允许时做联机断线重进，核对手牌、队友出牌位置和远端悬停。若第三方异常再触发，应看到对应的 `[卡牌管线]` 警告，重复相同错误时每个程序集和方法仅一条。若 #278 已消掉触发点，流程正常且没有警告也符合预期。
3. 离线夹具验证的是调用方可继续。实际画面、队友动画和第三方在抛异常前已修改的节点状态仍需实机确认。
