# 1.0.32.14：修复预览加载抢占活跃背景资源路径的回归

## 历史对比与确证
用户再次确认 1.0.32.13 可战损贞德非原色背景/点击仍失败，SFW 正常。最新日志最后明确出现作者 CharSelectCycle 的 live skeleton is not this mod's () — cycling off：读取到的骨架路径为空。

对比 1.0.32.11（7904236）与 1.0.32.12（5b31d33）：后者引入逐节点依赖绑定，并在本机成功回调后留下规范路径所有权。背景与随后小预览使用不同隔离图；新图 TakeOverPath 占用旧图的同一规范路径，Godot 会直接清空旧 Resource.ResourcePath，旧场景仍然引用该资源。作者 Palette.PageOf 和 SpineSwap.IsOurs 都通过活跃 atlas/skeleton 的 ResourcePath 识别包/调色页，于是同时失去颜色与点击资格。此前只验证缓存里谁获胜，没有模拟被挤出者路径被清空，导致回归测试漏检；1.0.32.13 增加的重绑处理也会被空路径挡住，未解决根因。

引擎行为核对：https://github.com/godotengine/godot/blob/4.5/core/io/resource.cpp#L65-L99 。Resource::set_path(p_take_over=true) 明确清空 existing->path_cache。此处是源码行为与用户日志、版本差异的共同证据；实际画面仍未在游戏中运行确认。

## 本次实际修复
- 新图抢占规范路径前，先让被替换的受管旧资源回到自己的不可变私有路径，保留活跃背景用于作者调色/战损识别的路径。
- 私有别名已被另一活跃资源占用时，使用保留原文件名和包路径的独立 retained 路径；不能为了保旧资源而反过来清空另一资源路径。
- 所有规范资源接管统一经过同一个入口；临时作用域恢复同样避免别名碰撞，保持联机/跨组所有权恢复与当前新图的规范缓存一致。
- 保留现有变体映射、内存预算、预读、开局/退出保护与战士保护区行为。业务代码只改两个共享资源管线文件，没有新增战损/调色兜底。

## 验证证据
- 增强缓存模型，精确模拟 take_over_path 清空被挤出者路径，而不只是 Dictionary 的覆盖。
- 将同一个新增测试与 1.0.32.13 的已提交 DLL 放在工作区外独立目录运行，明确失败：Preview loading must not blank the live background's skeleton path。
- 修复版通过活跃背景/预览连续 200 次换主、规范与私有别名碰撞、临时作用域幂等恢复检查。
- 将此专项纳入 tools/check-protected-characters.ps1 必跑，保留已有全部断言；真实 13 变体/战损档、十字军正式出招、角色预览/队列、内存与退出边界回归。
- CZN 五包、商店生命周期、切换资源生命周期、卡图预览专项通过。Release 0 警告 0 错误。

交付按原流程：四个目录三文件 SHA-256 一致，本地提交与 main/v1.0.32.14 推送。没有启动或控制游戏，离线结果不冒充实机画面确认。
