# 1.0.32.9：新商店首次进入显示缩小原版商人（2026-11-16）

## 证据与原因

作者反馈 1.0.32.8 的局内角色切换基本正常；新商店第一次进入时，已选商人皮肤却显示右下角缩小的原版商人。

godot.log 显示选择为 Merchant2CuteIIB。热切换曾通过独立运行场景加载当前资源，商人位置 (137.3, 223.3)、缩放 (0.18, 0.18)。后续新房间进入时，只有节点 Ready 的提供者回调与相同变换记录，没有对应的新商人独立资源实例化。皮肤代码已经运行，但仍绑定预加载缓存中的原版场景/骨架，把皮肤位姿用到了原版身体。

游戏 0.113 分拆 Standard/Blitz 商店并取消旧 NMerchantRoom.Create 工厂；原来的按当前皮肤重建预加载房间方法已经没有调用入口。现有基类/具体房间 Ready 只维护行为范围与部件接管，没有调用热切换所用的独立外观事务；旧 Tick 重试总开关关闭，不能作为首次进入保障。

## 修改

- 基类和具体商店 Ready 均接入首次外观队列；等待当前入树 Ready 流程结束后，用当前皮肤的独立场景重建商人按钮/身体及手部，复用已经验证的 TryRefreshMerchant 外观事务。
- 使用房间实例的弱键表保证每个新房间只排队一次；基类/派生类连续 Ready 不重复建模，不打开每帧重试旧通路。
- 回调确认原房间仍有效、仍在树内且为当前商店，重新确认仍有皮肤选择。离店后不操作旧房间，预览和原版选择跳过。
- 不替换玩家角色、不重新执行房间 Ready/玩法初始化、不重建库存数据；库存 UI 保留，按钮连接原来的 OpenInventory，商品与购买状态沿用原事务。

## 验证与限制

- Release 构建 0 警告 0 错误；LogicTests 通过。
- 商人生命周期：原有 200 次商店/火堆场景身份、初始化顺序、旧提供者隔离通过。
- 新增 200 个离线房间对象的首次认领和重复 Ready 去重；核对基类/具体房间真实调用入口、首次完成阶段连接外观事务且不调用玩法初始化。
- CZN 五个实包及真实共享框架归属回归、500 次切换资源生命周期专项通过。
- 未启动/控制游戏，以上对象与循环均为离线验证，实际商店画面仍未实机核验。
