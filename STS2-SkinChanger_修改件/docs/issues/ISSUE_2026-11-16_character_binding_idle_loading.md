# 1.0.32.12：角色外观同源绑定、必备预览与空闲加载

## 已确认原因
- 最新 godot.log 在切换时反复出现内存余量不足和 30 秒失败冷却。旧逻辑先提交选项，再捕获背景加载错误；结果新选项配旧画面。
- 目录加载优先选提供者默认场景，能覆盖选项声明的变体场景。
- 原生框架协作会关闭 SC 预览；奥斯提预览没有以当前角色为必要条件。
- 二进制资源对每个依赖根 IgnoreDeep 重解码，预算也对每个根重复计入全图，造成不必要分配和拒载。

## 修改边界
- 显式选项变体映射先于提供者默认映射。使用角色、完整选择（含变体/手动状态/框架后缀）的统一标识，隔离资源回调拒收过期结果，背景与模型实例标注来源。
- 角色下拉切换在刷新背景、头像、必备预览成功后再发布联机/局内刷新；失败回滚旧选择并重建旧展示。预读等待仍显示已提交选项，新点击替换旧请求，旧代次不得提交。
- 选人角色预览始终启用，不因框架协作隐藏；保留用户已有拖动/停靠功能。窄屏提供最小宽度；模型先暂存后替换，失败有界重试。奥斯提归属按选人界面实例保存，仅骨妹显示，避免旧界面回调影响新界面。
- 下拉、选人背景/预览/头像、局内头像/地图/战斗/火堆/商店角色继续通过同一有效角色选择和共享加载入口取资源。独立商人、奥斯提与显式头像设置的既有用途保留；不是强行把商人变成玩家。
- 完整依赖图按依赖优先加载，规范缓存只有匹配不可变私有源别名才能复用。外部组和联机临时所有权恢复；未绑定依赖或直接引用他者导出载荷则走旧深隔离。每根检查实际贴图估算，保留全图上限、缓存淘汰、失败熔断、原生余量限制。
- 单个文件 I/O 工作者每 256 KiB 重排；选择需求优先、取消后降级、队列/暖标记各上限 64。输入点击/键盘/手柄后暂停推测预读 350ms，鼠标移动不计；前台资源操作期间暂停文件预读和新原生预加载派发。纯文件预读不创建 Godot/Spine 对象，不阻塞 Common；黑屏/无操作空档可继续工作。
- 现有 Common 60 秒超时、原生最多一项在途、退出停止预读与保存/退出兜底保留。没有修改第三方包或启动游戏。
- 十字军/贞德保护代码保持行为；README 注明完整图逐节点隔离的适用条件。未动原始快照或用户已有删除。
