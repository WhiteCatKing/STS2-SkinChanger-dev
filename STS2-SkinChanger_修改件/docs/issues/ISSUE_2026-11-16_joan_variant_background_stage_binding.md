# 1.0.32.13：可战损贞德切换变体后的背景与点击绑定

最新日志可见：默认贞德连续 stage 1→2→3 正常；改选 variant:3 后，作者仍打印 click catcher/poller installed、cycling armed，但后续点击无 stage 记录，小预览已换色而背景未换。

静态核对实际 DLL：作者 CharSelectCycle 使用跨背景共享的 StageResources 数组，Poll/OnInput 还依赖 live skeleton 的归属；Palette 根据 live atlas/skeleton 路径识别调色页。因此接收器存在且 MouseFilter=Stop 并不能证明它仍能操作重建后的背景。SC 原先据此撤掉自己的点击处理；备用战损加载还优先取公共规范缓存，两包共用资源路径时存在借错包风险。

修改范围为保护区 CharSelectStageCycle、选人重建成功后的 Attach，以及显式私有根的目录查找：
- 选中包的真实 PCK 证明有后续战损档时，由 SC 持久接收层处理一次点击并 AcceptEvent，保留作者 WearEnabled 设置，避免双触发。不具有后续档位的 SFW 包不获得战损。
- 每个新选择/背景只执行一次绑定：通过当前选择的隔离资源重设同档背景骨架，并调用当前调色执行器 ApplyNow。原生作者组件及局内动画不修改。
- 真实包回归还确认 s2/s3 只在辅助文件中，原目录只查已索引 Assets 会产生空隔离图；显式请求的私有资源现从当前提供者 TryBuildAsset 延迟建索引，不扩大其他路径的覆盖归属。
- 三档 charselect 使用稳定的同一请求集合，复用同一隔离图，避免逐次点击生成三份别名/解码；不再先读公共规范缓存。
- 保留原有十字军动作、两包隔离、开局与退出保护。

验证：Release 0 警告 0 错误；保护脚本（安全/退出边界、真实 13 变体、十字军正式出招、手动变体/作用域）通过；新增两套贞德全部变体战损能力断言，以及隔离入口、三档稳定图、重建调色、独占点击与设置边界专项。另运行选人预览、商店、卡图回归。

测试不启动游戏；真实包数据和托管边界不等于实机色彩/鼠标命中验证，不宣称实机画面已确认。三文件按既有四处部署流程核对 SHA-256，提交 main 与 v1.0.32.13。
