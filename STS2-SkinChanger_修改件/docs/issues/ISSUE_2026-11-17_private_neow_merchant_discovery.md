# 2026-11-17：1.0.33.3 私有目录商人皮肤漏识别

## 证据与原因
- 用户包：mods/商人/雪霁改 一代涅奥替换商人；manifest neowmerchant，作者版本 1.3.2。
- 日志确认游戏已经发现 manifest 并初始化 DLL/PCK，但切换器未将它登记为商人选项。
- 真实 PCK 仅 12 项：npc_feminization2 下的 merchant/hand Spine 数据及 UI，未覆盖规范商人资源。
- DLL 的 NpcFeminization.MerchantRoomPatch 在 NMerchantRoom._Ready 后调用 MerchantRuntime.Attach；回调识别原商人骨架，再创建私有模型、手和交互视口。单独检查规范路径无法发现它。

## 修复边界
- 新增私有商人发现：同时要求实际私有 Spine 数据、DLL 引用同一命名空间及规范商人骨架、真实 Harmony 商店房间 Ready 元数据。只读 PE，不执行作者代码，不按包名硬编码。
- 先筛 PCK，再读候选 DLL；骨架说明读取上限 256 KiB，避免为无关包额外扫描程序集。
- 只登记 merchant 的独立运行时选项；完整保留原作者资源路径与设置，不将它误认成 neow/fake merchant/角色皮肤。不扩大普通房间补丁的全局皮肤判定。
- 选中后在预览及局内已提交的新商人节点上重放作者房间回调，保留原有停用、节点清理和库存状态。普通商人皮肤不走此新增分支。

## 验证
- 新 --test-private-merchant 使用真实 DLL/PCK，覆盖加载器探测、分组、完整身体/手/UI资源挂载、原生商店场景、选择事务及真实作者回调签名；无 DLL、无真实骨架的负例不得接管。
- 商人生命周期测试检查预览入口和提交节点后回调顺序；原有 200 个房间初始化及退出提供者隔离通过。
- 十字军/贞德保护脚本、瓦库默认/彩蛋及散图背景专项通过；Release 0 警告 0 错误。
- 未控制游戏进行实机渲染验证；第三方异步视口显示仍无法由离线 Godot 托管测试覆盖。
