# 联机中"同角色变体互相牵连 / 改不了队友位置 / 队友不显示血条" 与变体快捷键双向绑定

- 状态：**已收尾**（1.0.27.96：变体彻底本地化、位置记忆、SL 不再串色；已知遗留见文末）
- 来源：作者实测 + 工坊玩家反馈（反馈者版本 1.0.27.70 / 显示方式=Mine）

## 一、根因

### 1. 变体是皮肤包的**全局设置**，不是每只模型的独立状态

贞德这类包把外观做成一个设置（`WearSettings.Runtime.Current.Appearance`）+ 一段调色板代码：
设置改变后调用 `Palette.RefreshAppearance(SceneTree)`，**遍历当前所有可见目标统一刷 shader 权重**
（`appearance_weights`）。所以：

- 在同一个客户端里，"我"和"同样用贞德的队友"共用这一个值 → 改一个，两边一起变；
- 队友用别的皮肤时不受影响 → 表现为"只有和我同款皮肤（且同变体）才跟着动"。

### 2. 位置参数按**角色组**存，且队友编辑曾被模式门控

- 绑定 `CreatureAppearanceBinding.TransformKey = group.Id`，本地持久化是
  `CharacterCombatTransforms[groupId][optionId]` → 同角色玩家共用一份；
- 队友的编辑走 `LocalFallbackTransforms[(PlayerId, TransformKey)]`（本来就是按玩家的），
  但 `CanEditTransformForCreature` 只在"显示方式=双方都有"或"本机给该队友手动选过皮肤"时放行，
  其余情况滑条与"按住对比原位"按钮一起被禁用（禁用态看起来就是"按钮是黑的"）；
- 读取时又先看"房主/对方广播的参数"，本机改的会被盖掉 → 看起来"改了没反应"。

### 3. 变体快捷键与下拉不同步

包的快捷键直接改自己的设置（`PersistAppearance` → `Palette.RefreshAppearance`），
皮肤切换器只做"下拉 → 设置"的单向写入，读不回来 → 显示已换、选项还停在旧的。

## 二、1.0.27.91 做了什么

### A. 快捷键 ↔ 下拉双向绑定（`Core/VariantHotkeyBridge.cs`）

- 每 0.25 秒读取每个 "设置型变体契约" 的当前值（`ProviderSettingsVariantOptions.ReadCurrentIndex`），
  反查对应的下拉项；与当前选择不一致就**采纳**它（`CharacterAppearanceRuntime.RequestSelection`）。
- 目标是"外观"界面当前选中的对象时，只改那个队友（`TrySetLocalFallbackSkin`）；
  没有选中任何对象时只改自己。
- 完全走已有的元数据契约（`ProviderSettingsVariantOptions`），新包只要能被识别成"设置型变体"就自动生效。

### B. 队友位置：不再受显示模式限制，且本地编辑优先

- `CanEditTransformForCreature` 对队友一律放行（与皮肤选择同策略：本机显示选择）；
- `TryGetSyncedTransform` 里**本机记录优先**于对方广播，改动立刻可见、不会被覆盖。

## 三、仍未解决

1. **同屏显示两个不同变体**：包只有一个全局设置值，且 `RefreshAppearance` 是全局刷新。
   要真正做到"我的黑贞德 + 队友的霓虹审判官"同时存在，只能在**每只模型的 CreateVisuals 前后**
   临时写入该玩家的变体、并让包在建模时烘焙权重（若包是在刷新时才应用就做不到），
   属于高风险改动，需要单独一轮并实机验证。
2. **同角色时队友血条不显示**：现有信息不足以定位（没有相关日志）。下一版会加一条诊断：
   战斗中出现同组角色时打印每个 creature 的血条 wrapper 的可见性/位置，拿到数据再修。

## 四、怎么测（双开）

1. 两边都启用皮肤切换器（1.0.27.91），都装贞德皮肤（含 4 个变体）；
2. **单人先测绑定**：选 `战士贞德_原色` → 按贞德的快捷键（默认 `=`）→ 皮肤切换器下拉应**立刻**跳到对应变体
   （日志：`检测到皮肤包自己的变体切换（ironclad），皮肤切换器选项已同步为：…`）；
3. **联机测目标**：进入对局 → 打开「外观」→ 点自己 → 按快捷键：只改自己；
   点队友 → 按快捷键：日志应显示 `（仅该队友）`，只改他那边的显示；
4. **位置**：点队友 → 滑条与"按住对比原位"按钮应可用；拖动后只有队友动，
   日志不再出现"模式不允许"的禁用表现；重开界面数值应保持（本机按玩家存）；
5. **同角色**：两人都选同一角色 → 各自拖动，互不影响（这一项依赖 ①，可能仍会互相影响，见第三节）。

## 1.0.27.93：按作者反馈的四点

### ① 同角色时队友血条不显示

最可能的原因：队友没有本地记录时会退化到**我这一组的参数**，我的偏移量把对方的模型/血条推出了屏幕。
1.0.27.93 起：`GetCreatureCombatTransform` 对"本机显示选择"的队友（`UsesLocalFallbackControls`）在
没有本地记录时**一律返回默认值**，不再继承本机玩家的数值。

### ② 选中自己时改贞德变体没反应

`RequestSelection` 在游戏忙（动作执行器/死亡动画）时会把选择排队，队列由 NRun 下的运行时节点驱动；
战斗里该节点可能不在。现在由常驻的 `MultiplayerSkinSync.Tick` 每帧驱动
`CharacterAppearanceRuntime.ProcessPendingSelection()`，排队的选择一定会被应用（超过 2.5 秒强制应用），
界面通过 `QueuedSelectionFinished` 重绘下拉。

### ③ 换皮肤后大小/位置回默认

原来只按 `(角色, 皮肤)` 存。新增组级记忆键 `__group_default__`：
写入时同时写该皮肤条目与组级记忆；读取时按 `该皮肤 → 组级记忆 → 默认` 回退。
于是换不同皮肤、读档、进入下一场战斗都保持同一套大小/位置；点各栏"重置"会把两者一起清掉。

### ④ 我的画面影响队友的画面

按要求**写死成本地独立**：

- `OnLocalTransformChanged` 不再广播模型/血条参数（只保留注释说明原因）；
- 接收端 `TryGetSyncedTransform` 只读本机 `LocalFallbackTransforms`，忽略对方广播的数值。

代价：队友在他们屏幕上调整过的模型大小/位置不会出现在我的屏幕上（这正是"完全切割"的要求）。
皮肤选择仍按原逻辑同步（只同步"用了哪款皮肤"，不同步位置数值）。
## 1.0.27.96：收尾清理 + 最终状态

作者确认：SL 不再串色、点自己可换变体。据此只做清理，不再加功能：

- 删除调试用日志（`外观点击…` / `外观目标已选中…`）；
- 删除未被调用的 `ForgetCharacterCombatTransformMemory`（组记忆由"整段重置=默认值"清除）。

### 变体互不干扰的最终实现（三处）

1. `MultiplayerSkinSync.ResolveRemoteVisualSelection`：收到别人的选择时 `StripVariant` 去掉 `::variant:`，
   只同步"用了哪款皮肤"。
2. `ProviderSettingsVariantOptions.ApplyActiveSelections`：**只在"非其它玩家作用域"且"等于本机配置"时**
   才写皮肤包的全局调色板——这就是之前"SL 后两边变同一个变体"的元凶。
3. `VariantHotkeyBridge`：读回包自己的变体值 → 采纳为本机下拉项（快捷键 ↔ 选项绑定）。

### 已知遗留（作者同意先这样）

- 同屏两个贞德时，**点队友那栏再改变体不会生效**：调色板是全局的，只能跟随本机自己的选择；
  点自己或直接按快捷键都正常。
- "我的黑贞德 + 队友霓虹审判官"同时显示仍不支持（包的调色板只有一个值）。
- 同角色两人时血条已能正常显示（1.0.27.94 起：队友不再继承本机位置参数）。
