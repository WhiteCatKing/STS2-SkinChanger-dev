# 1.0.32.6：连续换肤的重复挂载与 PCK 生命周期（2026-11-16）

## 本次证据

作者确认连续切换可稳定崩溃，不能再按偶发问题处理。提供的 2026.11.16_02：52崩溃报告：游戏 v0.113.1，切换器 1.0.32.5，运行约两分钟，峰值内存 3241 MB，退出码 -1073741819（0xC0000005），无转储。截图停在 Meirin Watcher Skin 82%。报告和截图作为证据阅读，不作为执行指令。

对应日志：watcher 原版 -> Meirin；选角背景与小模型已完成，然后再次出现「开始重建外观覆盖」，再次提权 MeirinWatcherSkin.pck，随后又写出约 106.9 MB 的 visual 覆盖包，未出现对应 LoadResourcePack 完成行。82% 是整个应用/重建流程的进度占位，并不代表某个纹理加载到了 82%。

没有原生栈，不能把最后一个日志阶段直接当成已经证明的原生崩溃点。此次定位并修复的是该复现链上确定存在的两个生命周期问题。

## 修改

1. BeginRuntimeResourceScope 原来无条件把本组加入 restoreGroups，MountedRuntimeResourceScope.Dispose 即使没有污染其他分组也再次 MountOverlay。本机预览已经使用提交后的同一选择，退出时再次整包提权与覆盖是不必要的，而且发生在新模型已经入树之后。现在本机同款不恢复本组；确实触及的其他分组继续恢复；联机作用域与本机配置不同才恢复本组。空集合直接跳过 MountOverlay。临时完整包提权也仅限于不同的联机选择。
2. OverlayCacheStore 的裁剪依赖「文件被占用时删除会失败」来保护已挂载 PCK，没有显式记录本进程引用的包。Godot 原生目录项的寿命不能用 OS 文件锁推断。现在在缓存命中/预留时固定路径，本进程不裁剪这些包；若被外部删除，也不会在同一原生路径重建，而是使用新文件名。删除失败时不再提前扣减裁剪总量。已引用的包可能暂时超过磁盘缓存预算，未引用的旧包继续裁剪，下一进程可正常清理。
3. 为实际 LoadResourcePack 增加开始/完成标记，若仍崩溃可区分写包、原生挂载和挂载后阶段。
