## 2. 加载与本次风险修复

- GST2/PNG 解码前检查尺寸、截断/异常头和估算预算。Windows 使用可用物理内存与可用提交量的较小值，要求留下 512 MiB 余量；每个可能加载整张依赖图的根资源均重新检查，而不是只在开始时测一次。
- 资源为空、无效或零尺寸纹理时终止本次建模，不再跳过缺失资源继续交给 Spine。失败包冷却 30 秒，失败账本最多 256 项。
- 对资源保护异常，选角不再进入普通重建分支重试同一失败加载；尽量保留已有展示。新背景先实例化、绑定成功，再移除旧背景；已离树的选角请求停止执行。
- 只有经验证全部依赖可重用的图及不可变叶子资源使用缓存重用；二进制场景/资源的深度隔离保留。真实十字军、贞德包在测试中仍识别为不允许整体重用，未为了加速关闭隔离。
- 额外排查发现 RemoveOnlineSessionProvider 曾在离开对局时直接删已挂载运行包。现在只释放资源/索引引用，文件留到下一会话安全清理；不依赖操作系统是否允许删除判断 Godot 是否仍在使用。

## 3. 缓存与预读

| 项目 | 限制/处理 |
| --- | --- |
| 常驻独立资源 bundle | 最多 8 组，旧缓存估算预算 512 MiB，按使用时间淘汰 |
| 当前大模型例外 | 可保留当前正在使用的一组；单组估算上限 1536 MiB，并且必须满足实际系统余量。748 MiB 贞德不能被误判为不支持 |
| 单独资源引用字典 | 淘汰时一并移除旧 bundle 的二级引用，常规加载点最多 256 项；其他既有入口受下次修剪/余量检查约束，不宣称全进程硬内存上限 |
| 不可变 prepared overlay | 普通换肤保留按完整键区分的准备结果，减少重复生成私有包；本会话累计最多 256 个、约 2 GiB 数据预算，达到上限停止创建新包 |
| 已挂载 PCK | 不强行卸载、不在线删除/改写；Godot 仍可能引用。保留原有跨会话清理和固定路径保护 |
| 文件预读 | 一个 worker，一批至多 4 包/256 MiB，每包至多 128 MiB、8 秒；256 KiB 缓冲，暖缓存提示最多 64 项并校验长度/时间戳 |
| UI 等待预读 | 最多 10 秒后放行；页面/代次过期取消；按打开时长度读取，不能被不断增长的文件拖成无限循环 |

预读只暖操作系统文件缓存，提前准备当前/相邻选角皮肤包，不在 worker 调 Godot、不挂载包、不建立模型，也不提前构造第三方静态类。已预读且文件未变化的包，前台无需再次完整读一遍。没有实机帧耗基准，不能承诺完全消除卡顿。

原 Common 完成/60 秒超时放行保持，原生后台请求仍串行（1 个）；低内存不再派发剩余皮肤预加载。退出时新增 worker 取消，保留现有原生请求收尾、启动期间退出判定、原版保存完成后 12 秒兜底。未改 QuitCacheCleanup 或启动退出协调器。

## 4. 隐患检查结果

- 空值/异常：关键独立资源改为失败即停止、记录并冷却；没有用无休止空值重试替代错误处理。
- 循环/深度：选角节点递归改为迭代 DFS，引用去重并限制 8192 节点/待处理项；依赖展开最多 8192 步；优先级计算限制候选数+1 轮；文件读取由初始长度和取消期限双重限制。
- 缓存：检查并限制本 Mod 持有的旧引用与生成文件；释放引用不调用 Free/Dispose 销毁仍在使用的 Resource。低内存失败释放可选引用并请求非阻塞回收，不等待终结器，不阻塞游戏线程等待原生任务退出。
- 原生限制：Godot/Spine、GPU 驱动、第三方 DLL 的访问违规/分配器崩溃，以及已进入且不可取消的原生后台任务，不能靠 C# try/catch 或给所有循环套次数保证彻底隔离。日志没有原生转储，未声称消除所有崩溃或完成对 177 个 Mod 的全面形式化验证。
