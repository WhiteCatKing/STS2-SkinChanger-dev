# 近期优化计划与协作约定（2026-11-21 起，约一周）

> 给维护本仓库的 AI 和人看。这一周 yuinn（云）一方专做**性能和稳定性**；**第三方 Mod 的兼容**由维护者（白猫）一方负责。两边同时改代码时，按本文分工和约定来，避免互相覆盖。

## 1. 分工

| 谁 | 做什么 | 分支 |

## 2. 改到这些地方前先打招呼

云一方这一周会集中修改下面这些文件和函数。维护者一方修兼容时，如果需要动到它们：改动保持最小，在提交说明里写清改了哪一段；能放进单独兼容文件（`*Compat.cs`）或合同表的，就放进去。

- `Core/CardPortraitSessionCache.cs`：卡图会话缓存、释放
- `Core/SkinService.cs`：卡图加载（`GetOrLoadCardPortrait`、隔离卡图包 `EnsureIsolatedCardOverlay`）、覆盖包挂载（`MountOverlayCore`、`MountOverlayDelta`）、`PrepareSelectPortraitSafePack`
- `Catalog/SkinCatalog.cs`：`BuildOverlay`、`BuildAliasedResourceOverlay`、`BuildCardOverlay`、`ProtectGlobalCanonicalPackFile` / `IsSharedGameAtlasPath`
- `Core/ManagedSkinModLoader.cs`：提供者补丁的接管 / 保留判定（`IsManaged…` 那一组）
- 新增文件：原版完整性自检、诊断导出相关的新文件和对应测试

## 3. 这一周的优化项（按顺序）

1. **门禁与 UI 护栏**："不许丢的修复"逐条绑定测试，统一一键验收；切换器的 UI 注入点统一做异常保护，并且先入树、再调用依赖 `_Ready` 的方法。
2. **原版完整性自检 + 卡图性能基线**：
   - 启动时抽查关键原版资源（卡牌图集、选角头像、先古模板），先比 `.import` / `.remap` 指向和文件大小；发现被改写时，日志写明候选的写入方；
   - 记录卡牌总览首开、翻页、切包时的解码次数、耗时和内存，作为性能改动的验收基线。
3. **全局写入统一入口 + 卡图缓存复用**（两项按顺序做）：
   - 所有往全局资源系统发布文件的地方收进一个入口并记账；规范路径默认不发布，例外登记在表里；
   - 卡图依赖整条链都是同一来源、同一会话的私有路径时，复用共享图集，同一页只解码一次。
4. **合同表与诊断**：
   - 特定包的特殊处理（独立愚者皮肤、AI_silent 的卡面补丁拦截等）收进一张合同表；
   - 补丁接管情况按"目标 + 裁决 + 命中规则"输出到日志；
   - 游戏版本变化时汇总报告解析不到的路径和方法；
   - 提供一键导出诊断摘要。
5. **之后单独评估**：被游戏原生先加载的皮肤包，在没选中时由切换器临时卸下它挂在卡牌、模型上的补丁。

## 4. 现在就适用的原则

- **规范路径归游戏**：提供者的资源一律走私有别名路径；需要例外时写进例外表，并配真实包测试。
- **按真实合同接入**：特殊处理按包的实际类型、方法写成合同条目，配真实包用例；识别皮肤包时以 manifest 和程序集内容为准。
- **第三方自身的缺陷只做诊断**：日志里写清是哪个包、什么问题，给出玩家能做的处理办法。唯一的例外是"异常隔离"这类保护：不让别人的错误中断游戏核心流程（抽牌、出牌、建模）。
- **切换器排第一**：加载顺序问题先看启动提醒和日志里的 `[加载顺序]` 行。
- **性能改动用数据验收**：要附上改动前后的解码次数、首开耗时、常驻内存，并且通过 A→B→默认→A 切换不串图的回归。

## 5. 合并约定

- 两边的分支都基于维护者最新的 main。合并冲突只出现在版本文件时，保留 main 一侧再提升内测号。
- 合并后按 `maintenance-workflow.md` 第 4 步跑完整门禁，再交给维护者实机确认。
- 优化项每完成一项，就把新的"不许丢的修复"补进 `maintenance-rules.md`，同时补上对应的测试名。
