# 卡牌检视大图不跟随单卡皮肤：根因与修复建议

> 日期 2026-11-15。反馈者环境：游戏 `v0.113.1`（`d09d48e5`），皮肤切换器 `1.0.32.0`（工坊 10:21 版本）。
> 附带：`CardBigPortrait_检视大图跟随单卡皮肤.patch`（基于 `origin/main` = `52fe010`）。

- 状态：**未解决**

## 1. 现象

卡牌库网格里显示的是所选皮肤，点开这张卡进入检视大图（`NInspectCardScreen`）后，卡图变成别的样子。顶部单卡下拉显示的仍是所选的包。

| 单卡选择 | 网格 | 检视大图 |
|---|---|---|
| `card.compost => FoolWardrobeDamaged`（愚者包，图在自定义路径） | 愚者包的图 | **游戏原版** |
| 骨妹卡选了包 A，全局包栈里包 B 在上面（两个包都覆盖 `card_portraits/necrobinder/*.png`） | 包 A | **包 B 的图** |
| 所选的包恰好就在全局包栈栈顶 | 正常 | 正常（碰巧） |

## 2. 根因

v0.113 新增 `CardModel.BigPortrait`，检视界面在刷新卡牌后会用它再覆盖一次卡图：

```csharp
// NInspectCardScreen.UpdateCardDisplay（v0.113.1 反编译）
_card.Model = cardModel2;
_card.UpdateVisuals(PileType.None, CardPreviewMode.Normal);   // 这一步我们已贴好皮肤
_card.SetPortraitTexture(cardModel2.BigPortrait);             // 这一步又覆盖掉

// CardModel.BigPortrait
get {
    if (!HasPortrait) return Portrait;                         // 无独立 PNG 才退回 Portrait
    return PreloadManager.Cache.GetTexture2D(PortraitPngPath); // packed/card_portraits/<池>/<id>.png
}
```

- 皮肤切换器只补了 `CardModel.Portrait`（`CardPortraitResultPatch`）。单卡皮肤通过 `ResolveCardPortraitRequest` → `LoadIsolatedCardPortrait` 按单卡选择从隔离覆盖层取图。
- `BigPortrait` 不经过这个补丁，直接从全局资源读原版 PNG 路径，结果取决于"全局包栈里谁覆盖了这个路径"，与单卡选择无关：
  - 愚者包的图在 `res://waifu_assets/FoolWardrobeDamaged/portraits/`（115 张，原版路径 0 张）→ 读到游戏原版；
  - 骨妹多个包（`CuteNecrobinder-Cards-Rework-nsfw` 53 张原版路径 PNG，另有 `cutenecrobinder-nsfwv0.6`、`NNecrobinderCardArt` 等）覆盖同一批路径 → 读到栈顶那个包。
- 只影响**原版有独立 PNG** 的卡（`HasPortrait == true`）；没有独立 PNG 的卡会退回 `Portrait`，本来就正常。
- 旁证：`FoolWardrobeDamaged.dll` 单独运行时同时补了 `Portrait` 与 `BigPortrait`（`Main.cs` 第 91–92 行）；检测到 `Gurio.SkinChanger` 时它不装补丁，把卡图交给我们，所以这个漏洞只在两者同时启用时暴露。

## 3. 修复（补丁只改 `Ui/CardSkinControls.cs`，+20）

在 `CardPortraitResultPatch` 之后新增 `CardBigPortraitResultPatch`：给 `BigPortrait` getter 挂 `Priority.Last` 的 Postfix，复用 `CardSkinControls.ReplacePortrait`。

- 有生效的单卡/分组皮肤请求时，返回与 `Portrait` 完全相同的换肤贴图（同一个 `CardPortraitCache` 键）。
- 单卡选"游戏原版"时，`ResolveCardPortraitRequest` 会返回隔离的原版请求，因此也不会再被其他包的同名 PNG 顶掉。
- 没有任何皮肤请求（`request == null`）时不改 `__result`，保留游戏的原版高清图。
- 目标方法用 `AccessTools.PropertyGetter(typeof(CardModel), "BigPortrait")` + `Prepare()` 获取：正式版 `v0.107.1` 没有这个属性，整条补丁跳过。**不要写 `nameof(CardModel.BigPortrait)`**：按 v0.113 引用编译后，在 v0.107.1 上会找不到成员（与 `1.0.31.99` 的 `op_Inequality` 是同一类问题）。写法照抄 `SkinWorkshopService.cs` 的 `WorkshopRuntimeNoticePatch`。

应用（仓库根目录）：

```powershell
git apply "docs/issues/2026-11-15-inspect-card-bigportrait/CardBigPortrait_检视大图跟随单卡皮肤.patch"
```

## 5. 未覆盖的风险

- 单卡皮肤是动图/GIF（`CardSurfaceView`）、或卡图被外部编辑器接管（`ExternalCardVisualOwnership.Portrait`）时，`SetPortraitTexture` 仍会在 `UpdateVisuals` 之后把节点贴图换成静态的 `BigPortrait`，可能盖掉动图或编辑器的贴图。本补丁不处理这种情况。如果实机复现，可以在已有的 `CardInspectSkinDisplayPatch`（`UpdateCardDisplay` 的 Postfix）里，对这两类卡重新调用一次 `ApplySelectedPortraitToNode` / `StatefulCardArtView.Apply`。
- 换肤后检视图的清晰度与网格相同（用的是皮肤包自己的图），不再是原版的高清 PNG。这是预期结果。
