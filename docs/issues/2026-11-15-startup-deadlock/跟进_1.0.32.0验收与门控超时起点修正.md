# 跟进：`1.0.32.0` 验收结果 + 门控超时起点修正

> 接续同目录 `SkinChanger_启动死锁_根因分析与修复建议_给作者.md`。日期 2026-11-15。
> 本文件附带：`SkinPreloader_门控超时从Common开始计时.patch`（基于 `origin/main` = `52fe010`）、`logs_47-49_1.0.32.0验收.zip`。

## 1. 结论

1. **`1.0.32.0`（工坊 10:21 版本）在反馈者机器上修好了启动黑屏。**条件：**不放 `override.cfg`**（低优先级名额 = 2，最易卡）、冷缓存、148 个 Mod、预加载排满 48 个——**3/3 正常**。同条件旧版：预加载 48 档 2/2 卡、146 Mod 档卡。
2. **发现一个小缺陷（出自我们提供的补丁，非合入问题）**：门控的 60 秒超时从**首次排队**开始计时。冷启动时 SC 排队后自身初始化还要几十秒，游戏 `Common` 很晚才开始，**60 秒可能在 `Common` 跑到一半时到期**，导致"游戏预加载跑完再派发"的保护失效（F1 即如此）。因为 `MaxInFlight = 1` 仍给游戏留了名额，那局没有卡，但隔离效果打了折扣。
3. 附带补丁把超时改为**从 `Common` 开始时计时**，并增加"始终没见到 `Common` 开始"的 180 秒兜底。

## 4. 补丁内容（只改 `Core/SkinPreloader.cs`，+43/−11）

- `StartupGateTimeoutSeconds/StartupGateWatch` 拆成两个：
  - `CommonGateWatch` + `CommonGateTimeoutSeconds = 60`：**从 `Common` 会话首次被观察到"进行中"时开始计时**；
  - `ScheduleGateWatch` + `ScheduleGateTimeoutSeconds = 180`：仅当**一直没看到 `Common` 开始**时，从首次排队计时兜底。
- `GameCommonPreloadCompletePatch.Postfix`：先识别会话名；是 `Common` 时，完成 → 放行，未完成 → `SkinPreloader.NoteGameCommonStarted()`。读不到会话名时保持原行为（第一个完成的会话即放行）。异常仍然一律吞掉并放行。
- 应用：仓库根目录 `git apply "docs/issues/2026-11-15-startup-deadlock/SkinPreloader_门控超时从Common开始计时.patch"`（已用 `git apply --cached --check` 对 `52fe010` 验证）。
- **⚠ 未编译验证**（反馈者机器无 .NET SDK），请构建 + `LogicTests` 后再发布。

预期日志变化：正常情况与现在相同（`游戏预加载已结束（Common 完成）`）；兜底时变为
`Common 开始后超过 60 秒仍未完成，兜底放行` 或 `排队后 180 秒仍未见 Common 开始，兜底放行`。

## 5. 给玩家的说明更新

`1.0.32.0` 起不再需要 `override.cfg`。已放过的玩家可以删除；保留也无已知副作用。
