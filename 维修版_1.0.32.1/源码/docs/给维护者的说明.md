# 给维护者的说明

> 写给以后只用肥鱼（DeepSeek）维护这个 Mod 的人。草稿：Claude，2026-11-15。标「待补」的段落等对应任务交件后补齐。

## 1. 这次改了什么（一句话版）
在原作者 1.0.31.95 的基础上，做了三件事：
1. **熔断 / 防崩溃**（阶段 A）：某个补丁连续出错时自动停用，不让整个游戏崩掉。
2. **按需激活**（阶段 C）：商人、事件、背景、卡图、带状态卡图、先古、怪物、角色这 8 块的补丁改成"装了对应皮肤才装上"。
3. **零散修复**：涅奥商人、Merchant2CuteII 进店飞到左上角、CNR 卡图大图显示原版等。完整列表见 `CHANGELOG.md`。

玩家看到的行为和原作者版本一致。

## 2. 出问题时先看哪里
日志：`%APPDATA%\SlayTheSpire2\logs\godot.log`（每次启动会把上一份改名成 `godot<时间>.log`）。搜这几个词：

| 日志里的词 | 意思 | 下一步 |
| --- | --- | --- |
| `[熔断]` | 某个补丁出错太多次，已经被自动停用。后面跟着它的键，比如 `patch:character` | 按键名去第 4 节的模块表找到对应模块和文件 |
| `[防崩溃]` | 某处出错被拦下了，游戏没崩 | 看紧跟着的异常堆栈，定位到文件和行 |
| `[模块] 已注册「xxx」` | 启动时模块注册成功 | 8 个模块都应该出现 |
| `[模块] 按需调整：启用 … 停用 …` | 装卸皮肤包后，模块自动装上或卸下 | 一般不用管 |

进程直接消失、日志里没有 C# 异常，是游戏引擎层面的崩溃，多数是某个皮肤包跟不上游戏版本。先把那个包移出 mods 确认。

## 3. 改代码前必须知道的规则
1. **常驻补丁不要改成按需安装。** 清单见 `docs/refactor/resident-patches.md`，共 44 项（以清单为准）。每个常驻类（手动安装的是负责安装的方法）上方都有一行 `// 常驻·…` 标签，改方法体前先看清单里"碰了会坏什么"那一列。
2. **随从（奥斯提）和变体 / 战损的兼容桥不要重构。** 这些代码里的每个分支都对应原作者修过的一个问题，原因见 `docs/issues/`。
3. **新补丁放哪里**：
   - 只服务某一类皮肤的显示 → 加 `[FeaturePatch("<模块 id>")]`，归对应模块；
   - 选择入口、界面、存读档，或者好几类皮肤共用 → 常驻，登记进常驻清单，贴标签。
4. **不要在补丁里遍历整棵场景树。** 判断"某个界面开着没有"用单例或弱引用，写法参考 `EventCompendiumPreview.HasLivePreview`。
5. **补丁体出错要能熔断。** 新补丁的方法体用 `Safe.Run("patch:<模块 id>", …)` 包起来，键名和模块 id 一致。

## 4. 模块表
代码在 `STS2SkinChanger/Core/Features/<模块>/`，注册在 `Core/Features/FeatureBootstrap.cs` 的 `CreateFeatures()`。每个模块的熔断键都是 `patch:<模块 id>`。
- "启用"只看装了哪些皮肤包，不看当前选了哪个皮肤。
- "在用"时不会被卸掉，包括对局中、对应界面开着。

| 模块 id | 补丁类 | 什么时候启用 | 什么时候算在用 | 交件文档 |
| --- | --- | --- | --- | --- |
| `merchant` | 4 | 商人或假商人分组有非原版选项 | 商人房间或商人预览还在 | `merchant-migration-step1.md` |
| `event` | 4 | 任何事件分组或假商人分组有非原版选项 | 事件房间或图鉴事件预览开着 | `event-migration.md` |
| `background` | 2 | 背景目录有有效的非默认选项 | 背景界面开着，或当前战斗用着换过的背景 | `background-migration.md` |
| `card` | 11 | 装了卡图皮肤 | 对局中，或卡牌图鉴、卡牌大图开着 | `card-migration.md` |
| `stateful-card` | 11 | 有带状态的卡图 | 对局中 | `stateful-card-migration.md` |
| `ancient` | 8 | 先古分组有非原版选项 | 先古事件或先古图鉴预览开着 | `ancient-monster-migration.md` |
| `monster` | 1 | 怪物分组有非原版选项（不含商人） | 对局中或怪物图鉴开着 | `ancient-monster-migration.md` |
| `character` | 16 | 角色组或随从组有非原版选项 | 对局中 | `character-migration.md` |

交件文档都在 `docs/refactor/` 下，里面有每个判定的源码行号。新加模块就照 `monster` 的写法抄：Feature、Policy、Policy 测试三个文件，最后在 `CreateFeatures()` 里加一行。

## 5. 每次改完怎么验证
1. 改四个文件里的版本号第四位：`STS2SkinChanger/Entry.cs`、`STS2SkinChanger/SkinChanger.json`、`STS2SkinChanger/STS2SkinChanger.csproj`、`workshop/workshop.json`。
2. 构建：`dotnet build STS2SkinChanger/STS2SkinChanger.csproj -c Release "-p:GameAssemblyDir=<游戏目录>\data_sts2_windows_x86_64"`，要求 0 错误。
3. 离线测试：`dotnet run --project tests/STS2SkinChanger.LogicTests/STS2SkinChanger.LogicTests.csproj -c Release "-p:GameAssemblyDir=…"`，最后一行应是 `Skin Changer logic policy tests passed.`。
4. 实测：先停用工坊订阅的那份，把 `Gurio.SkinChanger.dll`、`thunninoiSkinManager.dll`、`SkinChanger.json` 放进游戏的 `mods\<任意文件夹>`，启动游戏，按改动写几步操作测；测完恢复。
5. 怀疑是老问题时，换回上一版对照一次，现象一样就不是这次改出来的。
