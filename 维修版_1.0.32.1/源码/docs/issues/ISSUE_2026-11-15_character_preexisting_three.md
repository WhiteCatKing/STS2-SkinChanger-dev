# 角色相关的三个老问题（1.0.31.110 实测发现，换 .109 对照现象相同）

记录：Claude，2026-11-15。云实测。日志备份在 `D:\mod\工作2\_test_backup_20261114\logs_110`。
结论：三个问题都不是阶段 C 角色模块引起的。.109 和 .110 的现象一致。

## 1. 魅魔战士血量换装[两档]（succubusIroncladHpWear）：选人界面一点就闪退
- 包位置：`mods\测试\魅魔战士血量换装\`。
- 启动时这个包自己报错：`patch failed for SuccubusCharacterSelect: Patching exception in method ... NCharacterSelectScreen`。它的选人补丁在当前游戏版本（v0.113.0）上装不上。
- 闪退前的最后几步（`godot2026-11-15T01.53.36.log` 末尾）：
  - `RebuildMountedFullRuntimeCharacterDisplay` 加载了 ironclad 的资源；
  - 日志显示"已刷新选角小模型：IRONCLAD/succubusIroncladHpWear；模型类型=NCreatureVisuals"；
  - 挂载了 1 个外观分组；
  - 然后进程直接结束，没有 C# 异常。这是引擎原生层面的崩溃。
- 怀疑方向：包跟不上游戏版本，缺资源或节点结构不符，导致 Spine 原生渲染崩溃。原作者报告第六节有"缺失资源进入原生 Spine 渲染导致黑块/崩溃"一条。
- 待查：确认是包本身的问题，还是切换器能提前拦住（资源能力检查失败时回退原版）。

## 2. 骨妹 + moe-necromod 骨手（随从）：位置跑远
- 现象：
  - 开局时骨手就离角色很远；
  - 换回原版骨手后存档读档，还是远的；
  - 重新选回 moe-necromod 骨手，位置会回正；
  - 但结束回合、新回合开始后又跑远；回正后退出重进，也会跑远；
  - 和别的骨妹包混用时，骨手会和角色叠在一起。
- 涉及：随从的位置、缩放基准（`CharacterAppearanceRuntime` 的排布快照 `PositionPlayersAndPets`、变换包装），以及 moe-necromod 自带的骨手换皮。都在共享常驻部分，阶段 C 没有动。
- 待查：新回合的哪一步会重置随从位置，以及读档后基准记成了哪个位置。

## 3. 四档战损皮肤：战斗中切换后不触发换装
- 现象：在战斗中切换到这个皮肤，受伤后不会换装；存档读档从头开始就正常。
- 涉及：变体或战损的选择门控、手动安装桥（`ProviderMenuGateCompat`、提供者行为激活）。阶段 C 没有动。
- 待查：战斗中热切换时，提供者的血量监听或战损状态有没有初始化。

## 处理结果（11-15 晚）
- **战损热切换**：1.0.31.111 修好（GPT）。战斗中切到战损皮肤时，补建这个包的血量检查计时器，切走或退出时清掉。
- **骨手跑远**：1.0.31.112 修好。热切换时改用游戏自己召唤骨手的位置公式（GPT）；云配置里误存的偏移 (192,-48) 已清零。
- **热换肤丢缩小**：1.0.31.112 修好（Claude）。重建模型时乘回游戏的临时倍率 `_tempScale`。
- **已知小问题（不修）**：已经缩小时，战斗中第一次切到战损皮肤会变回原大小，受伤触发换档后又恢复缩小。原因是战损包第一次检查血量时调用 `SetScaleAndHue`，把大小重设了一遍。正常开局不会遇到；要修只能为这一个包单独加补丁，所以不修。
- **魅魔闪退**：1.0.31.113 修好（GPT）。补上新旧导入格式的映射；加载前检查贴图页，缺页就回退原版。包自带的选人补丁装不上的问题不修（包没跟上游戏版本）。
