## 中文

### 适配《杀戮尖塔 2》v0.113.0

- 游戏删除了 `SingletonModel`，导致本模组的模型发现代码在补丁方法 JIT 时抛 `TypeLoadException`、启动即「致命错误」。改为反射获取，缺失即跳过。
- 跟随游戏接口改名：`NMerchantRoom.Create` → `_Ready`、`MerchantInventory.AddRelicEntry` → `CreateForNormalMerchant`、`NCharacterSelectScreen.SelectCharacter` 只收按钮、`StartRunLobby.ChangeCharacter` 增参。
- 补丁装配改为逐个补丁类容错：某个类装不上只跳过它，不再整包回滚，也不再让第三方皮肤包在初始化阶段炸掉整个会话。

### 商人皮肤

- 修「商人皮肤无法切换」：v0.113.0 把商店房间拆成 `NStandardMerchantRoom` / `NBlitzMerchantRoom`，`MerchantButton` 变成抽象属性、真实字段在子类里，旧代码反射拿不到 → 按实例真实类型解析，并在两个具体房间的 `_Ready` 末尾重新接管。
- 修「独立皮肤资源不是场景：merchant_room.tscn」：官方把该场景改名为 `standard_merchant_room.tscn` / `blitz_merchant_room.tscn`，按房间类型选择正确路径。
- 修「读档（SL）后商人显示旧皮肤」：改为房间真正就绪后再套用一次当前选择。
- 修「局内切换商人皮肤后位姿错乱」：三套商人包（工坊娘化、本地娘化、阿塔）共存时，切换后新节点从未重放过包自己的 `_Ready` 外观步骤，导致模型被放大并飞到左上角。现在每次热切换在进树前按「全等」匹配重放一次，并在补丁不在位时先补装。
- 修「选 b 却显示 a」：`Merchant2CuteII` 是 `Merchant2CuteIIB` 的前缀，历史上多处按 `StartsWith`/`Contains` 匹配导致混淆，现已全部改为全等匹配。
- 修「以 a/b 进入商店时模型缩成小点跑右下角」：进入房间那次包自己的位姿与我们的重放同时生效，缩放被乘性叠加两次（0.18×0.18）。新增数量级检测（`0 < 缩放 < 0.1` 视为重复套用）并还原为单次。
- 假商人事件的帐篷背景坐标校正，改为**仅当 NSFW-Event（工坊 3765802910）确实被启用时**生效；判据取游戏自己记录的已启用模组列表（本地安装同样适用），未启用时保持原版构图。

### 选人界面

- 修「随从专用皮肤出现在非骨妹角色的下拉里」：按声明过滤，只被随从分组引用的条目不再出现在其他角色页面。
- 修「奥斯提预览框在所有角色页面都显示」：预览框每帧自行恢复可见，改为面板内部按当前角色门控；只有死灵之缚显示，其余角色隐藏且不再复活。
- 修「角色皮肤整包重建时抛 `NSpineAutoPlayer` 骨骼动画数异常、导致卡死」：随从分组不走走整包运行时重建，并加异常兜底退回普通资源挂载。

### 性能与稳定性

- 覆盖包签名不再使用绝对路径（原写法每次启动都判为新内容，导致每次整包重写约 588 MB）。
- 延迟激活队列排序：最慢的包排在最后；启动阶段行为补丁改为 5 个同步 + 22 个延后，主菜单亮相耗时从约 1.9 s 降到约 1.5 s。
- 皮肤缓存加 8 GB 预算，超出后按最旧会话整目录清理（此前曾堆积到 63 GB）。
- 日志加 24 MB 上限并删除一批临时诊断输出（单份日志曾达 39 MB）。
- 不再误摘「游戏原生提前加载、本模组未接管」的第三方皮肤包的呈现补丁（此前会把商人包的补丁摘掉）。

### 其他

- 奥斯提替身（OstyDefectImpostor）适配：游戏把 `OstyScaleToSize(float)` 改名为 `ScaleAndPositionOsty(float, double)`，通过兼容层重定向其补丁查找。
- 修「商人皮肤崩溃后残留选择指向已停用副本」相关的容错。
- 第三次启动即崩（`0xC0000005`）经二分确认为 Steam 正在替换工坊文件的瞬时状态，非代码不兼容。

## English

### Adapted to Slay the Spire 2 v0.113.0

- The game removed `SingletonModel`, which made our model-discovery patch throw `TypeLoadException` during JIT and abort startup with a fatal error. Switched to reflection with a null-safe skip.
- Followed renamed game APIs: `NMerchantRoom.Create` → `_Ready`, `MerchantInventory.AddRelicEntry` → `CreateForNormalMerchant`, `NCharacterSelectScreen.SelectCharacter` now takes only the button, `StartRunLobby.ChangeCharacter` gained a parameter.
- Patch installation is now fault-tolerant per patch class: a class that no longer applies is skipped instead of unpatching the whole provider, so a third-party skin pack can no longer take down the session during initialization.

### Merchant skins

- Fixed "merchant skin cannot be switched": v0.113.0 split the shop room into `NStandardMerchantRoom` / `NBlitzMerchantRoom`, and `MerchantButton` became an abstract property backed by a subclass field, so the old reflection lookup returned null. Fields are now resolved from the instance's real type, and takeover runs at the end of both concrete rooms' `_Ready`.
- Fixed "independent skin resource is not a scene: merchant_room.tscn": the scene was renamed to `standard_merchant_room.tscn` / `blitz_merchant_room.tscn`; the correct path is now chosen by room type.
- Fixed "merchant shows the previous skin after load/SL": the current selection is now applied once the room is actually ready.
- Fixed "merchant pose breaks after switching skins in-game": with three merchant packs coexisting (workshop, local, ATA), the newly created node never replayed the pack's own `_Ready` appearance steps, so the model was scaled up and flew to the top-left corner. Every hot switch now replays them once before entering the tree, matching by exact id, and installs missing patches first.
- Fixed "selecting b shows a": `Merchant2CuteII` is a prefix of `Merchant2CuteIIB`; several historical `StartsWith`/`Contains` comparisons conflated them. All comparisons are exact now.
- Fixed "entering the shop with a/b selected shrinks the model to a dot in the bottom-right": on room entry the pack's own transform and our replay both ran, multiplying the scale twice (0.18×0.18). A magnitude check (`0 < scale < 0.1`) now detects this and restores a single application.
- The fake-merchant tent background coordinate fix now applies **only when NSFW-Event (workshop 3765802910) is actually enabled**, judged by the game's own enabled-mod list (local installs count too); otherwise the original framing is kept.

### Character select

- Fixed "companion-only skins appeared in non-Necrobinder dropdowns": entries referenced solely by a companion group are filtered out on other characters' pages.
- Fixed "Osty preview panel shows on every character page": the panel re-showed itself every frame; visibility is now gated inside the panel per current character, so only Necrobinder shows it.
- Fixed a crash where full-runtime rebuild of a character threw `NSpineAutoPlayer ... exactly 1 animation` and hung the session: companion groups skip the full-runtime rebuild and fall back to plain resource mounting with exception containment.

### Performance and stability

- Overlay pack signatures no longer include absolute paths (the old signature changed every launch and rewrote ~588 MB each time).
- Deferred activation queue is sorted so the slowest pack runs last; startup patching is now 5 synchronous + 22 deferred, cutting main-menu appearance from ~1.9 s to ~1.5 s.
- Skin cache gained an 8 GB budget with oldest-session eviction (it had grown to 63 GB).
- Log output is capped at 24 MB and temporary diagnostics were removed (a single log had reached 39 MB).
- Patches of third-party packs preloaded natively by the game and never managed by us are no longer stripped (this had been removing the merchant pack's patches).

### Other

- OstyDefectImpostor compatibility: the game renamed `OstyScaleToSize(float)` to `ScaleAndPositionOsty(float, double)`; a redirect layer fixes its patch lookup.
- Hardened handling of a stale merchant selection pointing at a disabled duplicate.
- A `0xC0000005` crash on every third launch was bisected to Steam replacing workshop files mid-launch, not a code incompatibility.
